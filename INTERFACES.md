# Jais Voice implementation contract

Native macOS app + Python supervisor (`scripts/run_services.py`) for the local Jais-ASR service (127.0.0.1:8790) and the MLX gateway (127.0.0.1:8788), + the Pi agent in RPC mode, a pipe child of the app (`scripts/run_agent.py`). One Jais 3 model, chosen by size (0.9B, 3.7B or 7B), serves both transcript cleanup and the agent; the advanced settings can replace it with an OpenAI-compatible API (see "Remote API").

## Native app: one turn
- The app owns the turn. Audio: complete WAV PCM signed 16-bit mono 16000 Hz, at most 30 seconds.
- 1. ASR: `POST :8790/transcribe` `{audio: base64 WAV, language?: ar|msa|fr|en|es|it}`; omit language for automatic detection. Response `{text, refused, truncated, language}`. A refused, truncated or empty transcript stops the turn.
- 2. Cleanup: `POST :8788/v1/clean` `{text, model_size?: "0.9B"|"3.7B"|"7B", endpoint?: {base_url, model, api_key}}`. Success `{text, elapsed_ms}`; failure 4xx `{detail: {code, message}}` with `cleaner_incomplete`, `cleaner_empty` or `cleaner_unavailable`. The raw transcript is never forwarded as a fallback. Explicit text input skips step 1 only. With **Correct transcripts** off (Settings → Assistant), step 2 is skipped and the raw transcript goes to the agent; no `correction` event is sent.
- 3. Agent: Pi RPC `prompt` with the cleaned text only (the raw transcript when cleanup is off). Before it, `new_session` when the conversation changes and `set_model {provider: "jais", modelId: "jais-3-0.9b"|"jais-3-3.7b"|"jais-3-7b"}` (or `{provider: "remote", modelId: <the API's model>}`) when the model changes.
- Cancellation or a new turn: cancel the turn task, send Pi `abort`. Events of a stale turn are never shown.
- Health: `GET :8788/health` → `{status, message, models: {"0.9B": {display_name, installed, status: ready|loading|unloaded|error|not_installed, error?}, …}}` and `GET :8790/health`. Memory: `POST :8788/models/{0.9B|3.7B|7B}/memory` and `POST :8790/memory` `{action: load|unload}`. Only one language model is resident; loading one unloads the other.
- The app starts the supervisor with `JAIS_MODEL_SIZE` set to the selected size; the gateway loads it, or another installed size when it is missing. With the remote API on, `JAIS_MODEL_SIZE=none`: no language model is loaded.

## Remote API
- Advanced settings (a separate window, opened from **Models**): an OpenAI-compatible base URL (`https://…/v1`), an optional API key, a model name and whether it is a reasoning model. The URL, model and flag are app preferences (`remoteAPI*`); the key is in `~/Library/Application Support/Jais Voice/remote-api-key` (mode 600), which the agent's file tools refuse to read. **Test connection** sends one short `POST {base}/chat/completions`.
- When on, it replaces the local language model for both stages; transcription stays local. Turning it on unloads the resident language model; turning it off loads the selected size. The app is ready once the ASR and the gateway answer, without a loaded language model, and no longer requires one to be installed.
- Cleanup: the app adds `endpoint` to `/v1/clean`; the gateway sends the same prompt to `{base_url}/chat/completions` (non-streamed, `temperature: 0`, `Authorization: Bearer` when a key is set, without the Jais template fields), drops a leading `<think>…</think>` block and applies the same refusals; an API or network error is `502 cleaner_unavailable` with the API's message.
- Agent: the app starts `scripts/run_agent.py` with `JAIS_REMOTE_BASE_URL`, `JAIS_REMOTE_MODEL`, `JAIS_REMOTE_API_KEY` and `JAIS_REMOTE_REASONING`; the launcher adds provider `remote` (`openai-completions`, `apiKey: "$JAIS_REMOTE_API_KEY"`, 128k context, 16k output) to the copied `models.json`, so the key never reaches a file. Pi detects the API's request format from its URL; `reasoning_effort` is sent only for a reasoning model. Another API, or turning it off, restarts the agent before the next turn.

## Models
- `models/catalog.json`: the ASR and one Jais 3 MLX build per size, each pinned to a Hugging Face commit.
- The app runs `scripts/models.py` (bundle resource `launch-models`): `list` → `{event: "catalog", models: [{id, kind, size?, display_name, installed, download_bytes?, disk_bytes, partial_bytes}]}`; `download <id>` → `{event: "progress", phase: download|verify|install, bytes?, total?}`… then `{event: "done"}`, `{event: "error", message}` (with `code: "no_access", repo, folder` when Hugging Face refuses the repository or its pinned revision) or, after SIGTERM, `{event: "cancelled"}` (resumable); `delete <id>` → `{event: "deleted"}`.
- At launch the app offers the missing required models (the ASR, and the 3.7B when no language model is installed). Deleting a loaded language model unloads it first.

## Panel events (in-process `WireEvent`)
- Types: status (stage: transcribing/refining/acting), transcript, correction, tool_start, tool_end, response_delta, complete, clarification_request, error.
- Mapping from Pi events: `message_update`/`text_delta` → response_delta (append-only; the panel shows text written before an action above that action, and only the text after the last action as the response); `tool_execution_start`/`_end` → tool_start/tool_end sharing `tool_id` (browser tools without their `mcp__browser__` prefix; result text bounded to 2500 characters); `ask_clarifying_question` → clarification_request; `agent_settled` → complete, or error when the assistant failed or returned nothing. Thinking blocks are never shown.

## Pi agent (`agent/`)
- Started as `pi --mode rpc --no-session` with `PI_CODING_AGENT_DIR=.runtime/pi-agent` (config copied from `agent/` at each launch; skills read in place with `--skill`, the user's `.runtime/skills` before `agent/skills`), offline, from the user's home folder (helpers work in `JAIS_AGENT_WORKSPACE`), without other extensions, prompt templates or context files; only `builtin:mcp` and `agent/extensions/jais`. Default model `jais-3-3.7b`. The app sends `set_thinking_level` (`low`, `medium` or `high`, the **Reasoning** setting, `low` by default), which Pi passes as `reasoning_effort`.
- Models: provider `jais`, `openai-completions` API on `:8788/v1` (streamed), IDs `jais-3-0.9b`, `jais-3-3.7b` and `jais-3-7b` (32k context; up to 16k output tokens, the gateway giving what the prompt leaves). The gateway samples the agent as the model cards recommend for thinking mode (temperature 0.7, top-p 0.95, top-k 20); cleanup stays greedy. Pi compaction is off: it estimated the raw page snapshots, fired after the first page and replaced the request with an English summary; the extension's `context` hook bounds what the model sees instead, and appends a reply-in-Arabic reminder to Arabic requests and their tool results. Retries are off.
- Tools: Pi's built-in `read`, `ls`, `find`, `grep`, `write` and `edit` (not `bash`; `grep` and `find` run the bundled ripgrep and fd); `shell_execute(command, reason)`, `macos_create_note(title, body)`, `ask_clarifying_question(question)` (ends the run); the app tools `desktop_list_windows`, `desktop_open_app(app, window?)`, `desktop_snapshot(app, window?, ocr?)`, `desktop_click(app, ref, button?, double?)`, `desktop_type(app, ref, text, mode?, submit?)`, `desktop_press_key(app, keys)`, `desktop_menu(app, path)`, `desktop_scroll(app, direction, ref?, pages?)`; and the Playwright MCP tools `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_press_key`, `browser_wait_for`, `browser_tabs` (`mcp__browser__*`), headed, isolated profile: Google Chrome when installed in `/Applications` or `~/Applications`, otherwise Playwright's Chromium, downloaded into `<runtime>/browsers` when the agent starts (browser calls wait for it).
- Skills: `agent/skills/<name>/SKILL.md` (`web-research`, `mac-apps`, `files`, `presentations`), and the user's own in the runtime's `skills/` folder, which Pi reads again at each `new_session` and which replace app skills of the same name. Tool calls a model writes as text are repaired at `message_end` and run. Pi lists their names, descriptions and paths in the system prompt and the model may `read` them; the extension also joins an area's skill to the first result of its tools in a request (browser, desktop, file tools). Skills from `~/.agents` and projects are excluded.
- Approval: before `shell_execute` and `macos_create_note`, the extension sends an `extension_ui_request` (`method: "confirm"`, `title`: tool label, `message`: JSON `{reason, details}`, 125 s timeout). The app answers with `extension_ui_response` `{id, confirmed}` from the “Actions on this Mac” setting: `never` refuses, `always` accepts, `ask` (default) shows the action in the result bubble with Refuse / Allow buttons; no answer within 120 s, or a stopped turn, refuses it. `JAIS_ACTION_PERMISSION` overrides the setting for scripted tests. A refusal fails the tool call with an instruction not to retry.
- App approvals: before the first read (`snapshot`, `scroll`, `open_app`) or the first control (`click`, `type`, `press_key`, `menu`) of an app in a request, the extension sends a confirm titled `App access` or `App control` whose JSON message adds `kind: "app_read"|"app_control"` and `app` (the app's name); the app words the question in the interface language. A control grant includes reading; grants end with the request. `desktop_list_windows` sends `kind: "overview"`: `never` refuses it, `ask` and `always` accept it without showing it. Once a window or a file was read in a request, `browser_navigate` to a host other than DuckDuckGo or a domain written in the request sends `kind: "web_after_desktop"` (title `Web page`, details: the URL).
- Desktop helper: the app passes `JAIS_DESKTOP_HELPER` (its own executable) to the agent; the extension starts `JAISVoice --desktop-helper` on first use. JSON lines on stdin/stdout: `{id, method, params}` → `{id, result}` or `{id, error}`; methods `status`, `reset`, `resolve {app, installed?}` → `{name, bundle_id, pid, running, tier, note?}`, `list_windows`, `open_app {app, window?}`, `snapshot {pid, window?, ocr?}`, `click {pid, ref, button?, double?}`, `type {pid, ref, text, mode?, submit?}`, `press_key {pid, keys}`, `menu {pid, path}`, `scroll {pid, direction, ref?, pages?}`, each answering `{text}`; actions append `### Snapshot` and the app's front window. It runs with Jais Voice's Accessibility (required) and Screen Recording (OCR only) permissions, refuses everything while the screen is locked, and exits when stdin closes.
- App tiers, enforced by the helper whatever the approval: `blocked` (Jais Voice itself, apps without a bundle identifier or Dock presence such as password prompts and system alerts, System Settings, Keychain Access, Passwords and password managers), `read` (terminals, code editors, script runners, Activity Monitor, Disk Utility and web browsers), `control` (other apps). The Apple menu is never used; clicking a window ref raises it, and a click never lands in the middle of an area; pointer clicks happen only where the target app's own window is under the point; keys and typed text are posted to the target process only; runs of digits and symbols (`128*47=`) are one key each, words never; a text area that already has text is only changed with an explicit `mode` (`append` or `replace`); password fields are never typed into.
- File approvals: the first file read of a request (`read`, `ls`, `find`, `grep`; the default path is the home folder) sends `kind: "files_read"` (title `File access`); reading the agent's own skills is never asked. Each `write` and `edit` sends `kind: "file_write"` (title `Write file` or `Edit file`, `reason` "Create this file?", "Replace this file?" or "Change this file?", details: the path and the content or the changed text). Never read nor written: credential stores (`.ssh`, cloud keys, shell startup files, `.env` files, keychains, browser profiles and cookies). Writes reach only the home folder, outside `~/Library`, hidden files and Jais Voice's own folders (runtime, agent configuration and skills, project).
- Shell: once approved, executed by the extension through `/bin/zsh -f -c`, new process group, minimal environment, cache working directory, 30 s maximum, output bounded to 8 KB, abort kills the group. Not a sandbox; macOS privacy permissions remain enforced. Page content and tool output never authorize commands.
- Per prompt: at most 50 browser, shell, Notes, app and file actions, and a third identical action among the last eight is refused; after a clarifying question no further action runs. Browser snapshot files are inlined from this process's output directory only. Older tool outputs are shortened in the model context (last 8 user turns kept).

## Runtime and ownership
- Project root: this directory; Python environment `.venv`; models, browser and Pi state under `.runtime/` (`JAIS_RUNTIME_DIR` overrides; the shared app uses `~/Library/Application Support/Jais Voice`).
- The supervisor owns the model services and stops them when the app's ownership pipe closes. The app owns Pi: closing its stdin is an orderly shutdown (Pi stops its MCP servers). No killing by name/port.
- Production uses actual ASR and Jais 3 inference. Test substitutes must be explicit and never masquerade as real inference.
